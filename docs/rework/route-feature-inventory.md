# UWE Route & Feature Inventory (Phase 2 Analysis)

Accurate snapshot of active routes, features, and their target placement in the new information architecture (IA) for the Hard UI/UX Reset. Generated by scanning `apps/studio/app` and `apps/portal/app`. Companion to `docs/rework/hard-ui-ux-reset-plan.md`.

Status legend:

- `rebind-now` — gets new shell/UI in the rework's first migration pass.
- `rebind-soon` — keep backend, new UI in a later pass; stays reachable.
- `legacy-ui-disconnected` — backend intact, removed from active navigation, UI re-bind documented as future work.

## 1. Active apps

- Studio (`apps/studio`) — DM/admin, port 3000.
- Portal (`apps/portal`) — players, port 3001.
- RTX Connector Client (`apps/rtx-connector-client`) — Tauri desktop.

## 7. Known route gaps / risks found

- Studio has no `/portal` route → `/portal` on the Studio origin yields Studio NotFound (QF2). Add defensive redirect + fix Cloudflare routing.
- `/worlds/[worldSlug]/[category]` has only `[slug]` children, no category index page; category listing is handled by `/worlds/[worldSlug]` via type filter (QF6). Guard invalid categories + empty states.
- `/api/dashboard-layout/[pageKey]` exists and is in route policy; 404 likely from proxy/path-prefix/auth interaction (QF1). Needs reproduction + regression test.
