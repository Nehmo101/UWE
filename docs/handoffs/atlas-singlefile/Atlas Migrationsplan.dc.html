00 · Fundament

Atlas wird eine Datei

Der React-AtlasEditor und die @uwe/atlas-Engine werden auf eine offline-fähige HTML/CSS/JS-Datei (Canvas API) refaktoriert — kein Parallel-Stack, kein Feature-Verlust.

1 Datei
Alles inline — kein CDN, kein Asset-Split für Kern-Tiles/Glyphen.
0 Verlust
Jede heutige Fähigkeit: übernommen, gemappt oder deprecated mit Pfad.
32 px
Tile-Raster, Canvas2D, scharf skaliert; Features bleiben normiert 0–1.
Kanonische Form: Das heutige Static-Export-Bundle (atlas/index.html + data.json + atlas-viewer.js) wird zur Single-File-Form konsolidiert. Der Viewer-Code und der Editor teilen sich eine Render-/Serialisierungs-Engine; der Editor ist Runtime, nicht der Daten-Owner.

02

Schema- & Migrationsplan

Rückwärtskompatibel: das heutige data.json (ohne schemaVersion) gilt als v1 und wird beim Laden zu v2 migriert. Features bleiben normiert 0–1; der Tile-Layer ist additiv.

v1 — heute (implizit)
{
  worldSlug, map, preset,
  builtinGlyphs[],
  pageLinks{}, nodes[],
  features[],   // Polygon|Path|
                //  Point|LabelAnchor
  objects[]     // x,y,scale,rot
}
v2 — Single-File (additiv)
{
  schemaVersion: 2,
  worldSlug, map, preset,
  builtinGlyphs[], pageLinks{},
  nodes[], features[], objects[],
  tileLayer: {            // NEU
    cols, rows, tile: 32,
    cells: { "c,r": biomeKind }
  }
}
EbeneRegelUmsetzung
ErkennungschemaVersion fehlt → v1migrate(doc) setzt schemaVersion=2, ergänzt leeren tileLayer
Featuresbleiben 0–1 normiert, unverändertdual gerendert neben Tile-Layer (Übergangsphase)
Tile ↔ Featureoptionale Rasterisierung großer Biom-Polygone → TilesrasterizeBiome() (opt-in, verlustfrei: Polygon bleibt erhalten)
ObjectspaletteItemId bleibt cuid; builtin via builtinGlyphKeyunverändert
DB-FeldAtlasMap.schemaVersion Int @default(1) + AtlasMap.tileLayer Json?additive Prisma-Migration, kein Breaking-Change
FehlerParse-/Migrationsfehler nie stilltry/catch → sichtbarer Degraded-Status, Roh-JSON bleibt ladbar
Regressions-Anker: scripts/atlas-cok-demo-seed.ts / Welt „Terra" wird als v1-Fixture geladen, migriert, neu serialisiert und gegen Erwartungswerte geprüft (atlas-single-file.test.ts).
03

Phasenplan

Kleine PRs, ein Arbeitspaket pro Branch. React-Editor bleibt bis Phase M4 lauffähig; erst dann Entfernung — kein Parallel-Pflegeaufwand darüber hinaus.

M0
Engine portieren erledigt
@uwe/atlas → ein Reintext-ES-Modul: Glyphen, Geometrie, Pfad-Glättung, Label-Layout, Presets, Export-Grid, prozeduraler Entwurf, Serialisierung/Migration, plus neuer paintTerrainBlobs-Renderer. Editor UND Portal importieren dieselbe Datei → atlas-engine.js.
M1
Single-File Editor erledigt
Chrome (Sidebar/Top/Status) + Canvas + alle Werkzeuge + fließender Blob-Tile-Layer + Autosave + JSON/PNG-Export → Atlas.dc.html.
M2
Portal read-only erledigt (Prototyp)
Gleiche Runtime, mode="view"; Klick = Drill-down/Wiki, kein Werkzeug, kein Schreiben; Sichtbarkeitsfilter auf Node und Feature/Objekt-Ebene → Atlas Portal.dc.html. Produktiv muss der Filter zusätzlich serverseitig sitzen (pnpm test:security).
M3
Studio-Einbettung erledigt (Prototyp)
Editor im <iframe>; postMessage-Bridge für Speichern, Sichtbarkeit, KI-Entwurf (Proposal→Review) und Handout → Atlas Studio.dc.html. Produktiv rufen die Host-Handler die echten Server-Actions.
M4
React-Editor entfernen Repo-Schritt
Sobald M1–M3 grün: AtlasEditor.tsx + ProceduralDraftPanel, RegionDescribePanel, AtlasStampGenerator und verwaiste Imports löschen; die Studio-Route mountet stattdessen den <iframe>. Die @uwe/atlas-Engine bleibt (ist nun die Modul-Quelle). Gate: pnpm ci:light. Findet außerhalb dieses Prototyps im Monorepo statt.
04

Sicherheit & Gate

  • Portal-Filter: Sichtbarkeit serverseitig vor Serialisierung; dm_only darf nie in ein Player-Bundle gelangen.
  • KI: nie Auto-Apply an Canon/Brain — Proposal/Draft/Review; personal_brain hart lokal.
  • Tests: @uwe/atlas-Unit (Seed-deterministisch, Serialisierung, Migration) + atlas-single-file.test.ts.
  • Manuell: alle Werkzeuge, Drill-down, Export JSON/PNG, Static-Export offline öffnen.
  • Gate: pnpm quality:quiet / pnpm ci:light grün; RTX/lokale Inferenz nur LAN.
